# แนวทางภาษาไทยของ DJAI

เอกสารนี้เป็นข้อกำหนดร่วมสำหรับแอปที่รันได้ทั้งสามชุดใน repository นี้ ได้แก่ Voice Sales Agent ที่ root, `DJAY_Bot_SaaS_Platform` และ `FlowBot_V1_App`

## หลักการที่ต้องคงไว้

- ภาษาไทยเป็นภาษาเริ่มต้นเสมอ ทั้งหน้าเว็บ แดชบอร์ด วิดเจ็ต อีเมล การแจ้งเตือน ข้อมูลตัวอย่าง ข้อความผิดพลาด วันที่ ตัวเลข และสกุลเงิน
- ภาษาอังกฤษแสดงได้ต่อเมื่อผู้ใช้เลือก `EN` เท่านั้น การตั้งค่าจะถูกเก็บใน browser และลิงก์ที่เกี่ยวข้องต้องส่งต่อ locale
- ห้ามใช้ภาษาอังกฤษเป็น fallback ที่ผู้ใช้มองเห็นได้ หากไม่มีคำแปลไทย ให้เพิ่มคำแปลก่อนเผยแพร่
- ชื่อผลิตภัณฑ์ ชื่อช่องทาง และคำเทคนิคที่เป็นชื่อเฉพาะ เช่น DJAI, LINE, WhatsApp, API, URL และ Webhook คงรูปเดิมได้
- ฟอนต์และระยะบรรทัดต้องรองรับวรรณยุกต์ไทย และต้องตรวจข้อความที่ยาวกว่าภาษาอังกฤษบนหน้าจอขนาดเล็ก

## รูปแบบภาษาและข้อมูล

- ใช้ประโยคสั้น สุภาพ และเป็นธรรมชาติ ไม่แปลคำต่อคำจากภาษาอังกฤษ
- ปุ่มใช้คำกริยาที่บอกผลลัพธ์ เช่น “บันทึกการตั้งค่า” หรือ “สร้างนัดหมาย”
- ข้อผิดพลาดต้องบอกสิ่งที่เกิดขึ้นและสิ่งที่ผู้ใช้ควรทำต่อ โดยไม่เผยรายละเอียดภายในระบบ
- วันที่ภาษาไทยใช้ locale `th-TH`; เมื่อเลือกอังกฤษใช้ `en-GB`
- ค่าเงินไทยใช้ `THB` และรูปแบบตัวเลขตาม locale ที่เลือก
- ตัวแปรในข้อความ เช่น ชื่อ จำนวน และระยะเวลา ต้องอยู่ในตำแหน่งที่อ่านเป็นภาษาไทยได้เป็นธรรมชาติ

## เอกสารกฎหมาย

ข้อกำหนดการใช้บริการและประกาศความเป็นส่วนตัวเป็นเนื้อหาที่ต้องได้รับอนุมัติ ไม่ควรแปลโดยอัตโนมัติใน production ระบบ SaaS จึงอ่านคำแปลจาก legal bundle ที่อนุมัติแล้วเท่านั้น และจะแสดงสถานะไม่พร้อมใช้งานแบบปลอดภัยหากยังไม่มี `translations.th` ผู้ใช้ที่เลือกอังกฤษโดยชัดแจ้งจึงจะเห็นต้นฉบับอังกฤษ

โครงสร้างที่ต้องเพิ่มในแต่ละ document:

```json
{
  "translations": {
    "th": {
      "title": "ชื่อเอกสารภาษาไทยที่ได้รับอนุมัติ",
      "summary": "สรุปภาษาไทยที่ได้รับอนุมัติ",
      "sections": [
        {
          "heading": "หัวข้อที่ได้รับอนุมัติ",
          "paragraphs": ["เนื้อหาที่ได้รับอนุมัติ"]
        }
      ]
    }
  }
}
```

ต้องให้ที่ปรึกษากฎหมายยืนยันว่าคำแปลตรงกับ version และ effective date เดียวกับต้นฉบับก่อนนำ bundle ไปใช้

## จุดที่ต้องตรวจเมื่อเพิ่มฟีเจอร์

1. เพิ่มข้อความไทยและอังกฤษพร้อมกัน โดยไทยเป็นค่าเริ่มต้น
2. ตรวจทั้งข้อความคงที่ ข้อความจาก API, validation, toast, modal, email, CSV, seed data และข้อความในวิดเจ็ต
3. ตรวจหน้าจอมือถือ การตัดบรรทัด ปุ่ม และตารางด้วยข้อความไทยจริง
4. ตรวจ keyboard navigation, accessible name และการสลับ TH/EN
5. รัน typecheck, lint, tests และ production build ของแอปที่แก้

การตรวจอัตโนมัติของ SaaS อยู่ใน `scripts/check-thai-first-locale.mjs`; อย่าปิดหรือข้าม check นี้เมื่อเพิ่ม surface ใหม่
